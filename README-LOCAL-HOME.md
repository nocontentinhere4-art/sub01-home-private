# SUB-01 private home development

This repository is for the new inhabited home only. Work and validation stay on localhost. Do not link it to the production Railway service, change production variables, merge it into the public SUB-01 repository, or deploy it without a separate explicit instruction from the owner.

The source snapshot includes the brain/server needed to run locally. See docs/inhabited-home.md for the implemented home and device tests. Previous production rollout was reverted; the public site uses its original deployment.

Start with HOME_ENABLED=1, HOME_ENTRYPOINT=1, BROWSE=1, MIND=0, CLIPS=0 and a local-only SUB01_ADMIN_TOKEN. Bind live_server.py to 127.0.0.1. Keep local runtime data outside Git.

`python scripts/start_home_local.py` enforces loopback binding and disables paid integrations, with one owner-approved exception (2026-10-13): the eye. When the private environment or the git-ignored `.env` has a `REPLICATE_API_TOKEN` (or `SUB01_EYE_REPLICATE_TOKEN`), it is handed to the eye alone as `SUB01_EYE_REPLICATE_TOKEN` and the server starts with `--eye`; `REPLICATE_API_TOKEN` itself stays blank, so the browser's eyes, the diary text, the mind and every other integration remain unpaid. The eye spends only while he sleeps (NREM: closed eyes, REM: dreams) or is outside (what he sees on the way), never awake at home, within the existing daily eye cap ($1.00, never raised by the script; `costs.py` ledger). The token is never printed. `--no-eye` keeps it off; frames go to the ignored `out/eye/`. The GPS map and the separate "sees" page are gone: `/map`, `/life`, `/life.html`, `/sees` and `/world.html` lead home. Default time is the real Tokyo clock. For a separate nighttime test use `--port 8801 --start 23:00 --time-scale 2 --data-dir /tmp/sub01-night-test`; the original clock ignores a custom start at scale 1. Keep these test instances separate from the main local runtime.

The local runtime now starts the CPU spiking model at 500,000 neurons (505,000 after the tested daily growth), without a GPU/cloud connection. Use `--no-spiking` for light visual QA or `--neurons N` for a smaller test network. This does not assert improved comprehension merely from the higher neuron count.

The desk now uses the existing detailed CC0 mouse and an offline extract of the owner's existing keyboard (153 KB, 4,020 triangles); it never loads the old room to display these. `tools/extract_home_keyboard.mjs` rebuilds that extract with the vendored Three.js helpers and a tooling installation of `three` available on the module path. Replaceable fallbacks stay outside architecture batching; stale contact atlases reject changed triangle counts as well as changed bounds. Explore mode now accelerates and brakes gradually, with bounded speed and collision handling; `node tests/js/home_walk_check.mjs` verifies those limits and frame-rate consistency.

Day/night lighting now follows that same clock, including moving sunlight and lit pendant/bedside fixtures. `node tests/js/home_lighting_check.mjs` checks the full daily cycle; home/API/growth tests returned 11 passed. The 23:00 room was visually checked at approximately 46 fps after loading on this Mac. This is one machine, not a general performance guarantee. Local Chromium remains blocked by this Mac's sandbox; the guest Linux computer boots using verified cached assets.
