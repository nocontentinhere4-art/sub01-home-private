New evidence on SUB-01's frame time (UE 5.8.3 editor build run as UnrealEditor-Cmd -game, Linux, Vulkan). Decide the next experiment, max ~300 words, numbered.

1. The render thread time is a SAWTOOTH, which explains the +-5 fps "noise": it rises ~0.5 ms per minute (e.g. 15.3 -> 18.9 ms with cam2 on, 9.4 -> 13 ms overnight without cam2) and drops back at EVERY garbage collection (CSVEvent "GC" at 13:08:59, 13:16:07, 13:23:39; period ~7 min). Before/after a drop (CSV, 2400 frames each side): RenderThreadTime 18.6 -> 15.3, Exclusive/RenderThread/EventWait 4.9 -> 2.6, RenderOther 4.45 -> 4.09, all other render stats within 0.2 ms; GPU 10.6 flat; GPUSceneInstanceCount 1628 flat; draw calls flat.
2. Per-thread CPU (/proc, 10 s samples) is FLAT through the rise (render thread 64-67% of a core, RHI 65%, workers flat) while fps falls 48.9 -> 44.8. Host load flat (~16% of 48 CPUs, SMT siblings idle), no cgroup throttling.
3. Stopping the in-game monitor's frame source (the bridge created a new UTexture2D per frame, ~2/s) did NOT stop the rise.
4. The process uses Mimalloc (editor default; log "Memory allocator used: Mimalloc"); after GC the engine calls FMemory::Trim() -> mi_collect(). Hypothesis: allocator degradation (cross-thread frees accumulating / fragmentation) slowing allocations across render thread and task workers until the post-GC trim.
5. Correction: r.Vulkan.CpuWaitForFence is read-only at runtime ("is read only!"), so all its earlier A/B legs were A/A.

Proposed: relaunch the same build with -binnedmalloc2 (what packaged games use on Linux) and run 2-3 GC cycles (~20 min) checking whether the sawtooth disappears and the low level holds; if Binned2 misbehaves, try -binnedmalloc3 or -ansimalloc. Alternative/complement: a shorter GC interval via -ExecCmds "gc.TimeBetweenPurgingPendingKillObjects 30" (costs a GC hitch every 30 s). Also CpuWaitForFence=0 via launch-time ini on a later relaunch. Decide order and acceptance (what pattern proves or refutes the allocator hypothesis), and risks of switching the allocator in an editor-build process.
