PROPOSAL B: monitor feed privacy gate (fail closed)
B1. Signals, any one => PRIVATE:
  (a) layout.jsonl: the last line (tail read like the director's read_tail_records) is a privacy line (reason == "privacy", same rule as the director's privacy_cut, layout name ignored). No file => no cut (normal state). Last line not a JSON object (half-written) => PRIVATE until a valid last line (fail closed; transient). Any other read error (EACCES, EIO...) => PRIVATE. Checked every 0.25 s (stat size/mtime/inode, re-read on change, forced re-read every 5 s).
  (b) runner GET /pc/state (X-Admin-Token from SUB01_ADMIN_TOKEN or --token-file; never logged) polled every 0.5 s, timeout 1 s: PRIVATE when privacy == true (the bathroom privacy, sources native/home); when pc_mode == "vagon" and vagon.kind == "workstation" and NOT (vagon.connected is true and vagon.phase == "connected") (same predicate as the runner's privacy_locked); when the request fails, is not HTTP 200, is not JSON, lacks the privacy field, or the last good answer is older than 2.5 s. pc_mode chromium or the Vagon streams kind: only (a) and the bathroom flag apply.
  (c) startup: PRIVATE until both (a) and (b) have answered non-private at least once.
B2. Hysteresis: closing is immediate on any single PRIVATE observation. Opening needs every observation to be clean for --resume-after 1.0 s (continuous).
B3. Behaviour while PRIVATE: stop the x11grab ffmpeg at once (an asyncio Event wakes the read loop; no screen frame is offered after the gate closed, frames already cut from ffmpeg's pipe are dropped), drop the FifoSink's pending tail of a partly written screen frame (the reader resyncs on SOI anyway), and write a NEUTRAL frame (solid grey 72,74,78 like the runner's "PC not connected" picture, same size as the feed, rendered once at start with ffmpeg lavfi color -> mjpeg; kept in memory) into the FIFO immediately and then every 0.5 s (2 fps: keeps a reader that connects mid-cut and any freshness check fed, costs the CPU-bound game almost no JPEG decoding). If the neutral JPEG cannot be rendered: write nothing (stop writing), health says so.
B4. On reopening: a NEW ffmpeg is launched (so no frame captured during the cut can come out of an old pipe), screen frames flow again.
B5. Health /healthz adds: "privacy": {"private": bool, "reasons": ["layout_cut", "runner_privacy", "vagon_not_connected", "runner_unreachable", "layout_unreadable", "starting"], "since", "last_runner_ok_age_s", "layout_cut_id"}, "showing": "screen"|"neutral"|"nothing", "neutral_frames". No secrets, no URLs with tokens. events to stdout (the supervisor log): privacy_on/privacy_off with reasons.
B6. No way to switch the gate off on a real display: --no-privacy-gate is accepted ONLY together with --test-source (lavfi), for local tests.
B7. The existing idle logic stays: without a reader ffmpeg is stopped after --idle-stop; neutral frames are written only while a reader is connected.
