Offline assessment: is historical exact-header-overlay necessary?

Conclusion: required to reproduce the recorded build invocation; NOT proven intrinsically required by current C++ source. Available evidence cannot distinguish (A) supplying ordinary missing authentic headers from (B) redirecting existing headers to another exact vendor revision or other contents. Do not claim either without mapping/target bytes. The local native source has normal includes, not a reference to overlay JSON. The overlay is injected by the external compiler flag in all v22–v24 wrappers.

Evidence distinctions
1. tools/private_home_engine_extract.py:4–36 selects every engine-full.zip member, copying regular files and symlinks. It is not an overlay generator and contains no header substitutions. Its completion marker verifies executable presence and records total bytes, not a cryptographically authenticated engine/source revision or exhaustive SHA manifest.
2. tools/recover_private_engine_runtime_overlay.py:74–87 deliberately excludes Engine/Source entirely; also excludes plugin Source/Intermediate, platform Source/Intermediate and compiler SDK trees. It verifies selected members using archive CRC/size and records compiler_complete:false (line156). This supports a historically incomplete build environment, not the conclusion that ALL later overlay entries were missing rather than replacements. Current SDK presence proves later additions beyond this particular restore scope.
3. tools/pod/onpod/build-v22.sh/v23.sh and build-v24.sh pass -AdditionalCompilerArguments=-ivfsoverlay <project-parent>/exact-header-overlay.json. They neither produce the mapping nor describe its entries. Therefore replaying these commands requires that file and its resolved external targets. Removing the flag changes the build input and needs separate evidence/review.
4. Current engine5.8.3 actualCL58210709/compatible55116800 and compiler20.1.8 were independently read by root. Those identifiers establish declared versions, not hashes of every consumed header or equivalence to overlay inputs. Existing v24 .so/source hashes establish preserved outputs/source, not a reversible derivation of header contents.
