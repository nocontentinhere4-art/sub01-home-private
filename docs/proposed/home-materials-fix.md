## 1. Bed: is the mustard intended or a wrong assignment?

`tools/assemble_home_blender.py:380-388` (quoted exactly):

```python
        upholstery = 'upholstery' in material.name
        tint = '#b99845' if 'teal' in material.name else '#f7f4eb'
        set_base(material, tint if upholstery else '#e7dcc9',
                 linen_image if upholstery else oak_image, 2 if upholstery else 1)
        ...
        set_roughness(material, .92 if upholstery else .82, old_factor)
```

`set_base` (lines 209-231) sets Base Color = `MixRGB MULTIPLY(image, color(tint))`
with a Mapping scale of `repeat`; `color()` (lines 174-177) linearises the hex
correctly (IEC sRGB curve). The Blender glTF exporter turns an image × constant
MULTIPLY into `baseColorFactor` (linear) × `baseColorTexture`, and the mapping scale into
`KHR_texture_transform.scale` = [2, 2]. This matches root's real-GLB facts (roughness 0.92,
UV 2×). `linen_image` is `base_image(pillow.data.materials[0])` (line 203). In the V4 export
the pillow is `M.linen = pbr('rough_linen')` (home.js:193). Root should confirm this with
`--glb`.

Reading for root:
- If the duvet and mattress read as blue-grey and only the headboard reads khaki/olive, the
  assembly is behaving as written. In that case the "warm" problem is the **blue linen
  texture**, not a wrong assignment.
- If the **whole bed** reads mustard, that is NOT what the assembly writes. Likely causes,
  most likely first:
  1. the teal material/MIC is bound to more slots than CC0_queen_1 (a slot mismatch);
  2. a tint was applied without its texture (#b99845 alone is mustard);
  3. a double sRGB conversion, which gives the dark mustard-brown #44330a only on the
     headboard and does not turn the duvet mustard.

  The mapping dry run in `tools/unreal_home_materials_fix.py --mapping-check` (next
  increment) enumerates each bed/sofa component slot and compares it with these groups.
- Warm light alone cannot make Y 0.36, hue-212° blue-grey fabric look mustard.

Minimal fix options (no change to the assemble script):
- (a) A MIC child of the real bed upholstery material that overrides **only its existing
  base-colour factor parameter**, enumerated first. It cancels the linen scan's blue cast to
  give the intended ivory. The factor must exist on the parent; otherwise it fails closed.
- (b) If the mapping check finds a slot mismatch, re-point that slot to the material of its
  source group (exact component path + slot index; backup + `--restore`).

|---|---|---|
| CC0_queen_1 (headboard) | #b99845 | #686436, Y 0.124, hue 56° (khaki/olive, not clean ochre) |

  The designer clearly intended a warm ivory duvet ("ivory bedding" in home.js:900) and an

| group | `bed-balanced` linear factor | predicted mean |
|---|---|---|
| headboard | (1.0269, 0.4625, 0.0587) | #937835, Y 0.20, hue 43° (the #b99845 hue) |

## 4. The patch: `tools/unreal_home_materials_fix.py` + `tools/home_materials_spec.py`

| preset | default | targets (by source material name / actor prefix) | override |
|---|---|---|---|

| `bed-balanced` | no (alternative; refused together with `bed-intended`) | same 4 | white-balanced factor (table above) |
| `sofa-intended` | no | actors `Haven_linen`, `Haven_seams` (1 material each) | #737e87 / #58616a linear |

| `bed-wood-roughness` | no | `Original walnut grain`, `Original oak grain` | `RoughnessFactor` .82 → .50; only if the real value is .82 |

| `metal-espresso` | no | powdercoat .25 → 0; galvanized steel .78, blackened steel .75, champagne bronze .80 → 1 | `MetallicFactor` only, and only from those exact current values |

Scalar presets change nothing but the named scalar. Every preset is independent. The bed
mapping gate only blocks presets that touch bed materials (`bed-*`).

Guarantees (each covered by `tests/test_home_materials_fix.py`, fake `unreal`):
- **Mapping first.** The bed slots are compared with the measured source groups: material name
  ⇄ `CC0_queen_N` actor/component/mesh identity.
  - Any slot bound to another group's material, a group with two materials, the headboard
    material on another bed part, a missing group or an ambiguous identity is a refusal.
  - Root's read-only inventory (`tools/unreal_home_visual_inventory.py`, schema
    `sub01-private-actual-visual-inventory-v1`) is parsed directly by `--mapping-check
    --inventory` (exit 2 when it is not safe). The live enumeration is the fallback.
- **No invented parameters.** Only a name the editor enumerates on the real parent is used
  (`BaseColorFactor` / `Base Color Factor` / `BaseColor_Factor`, first match). If none
  exists, the target is refused.
  - The owned `SUB01_MatFix_Master` is used only with the explicit `--allow-owned-master`.
    It provides BaseColorTexture × Tint with optional Desaturation, Roughness,
    NormalTexture × NormalStrength, UVTiling and Metallic. It reuses the original texture
    assets and checks their colour space: base colour sRGB, normal/roughness non-sRGB.
- **Current factor guard.** It must be white (tint lost) or already the intended value
  (the material is then skipped). Anything else is a refusal.
- **Texture signature.** In live mode the base texture must be 512×512 (real Image_14), or
  the repo's 511×512 / 1024×1026 linen. All four bed materials must share one texture.
- **Additive only.** Owned MICs `/Game/Sub01Home/MaterialFix/SUB01_MatFix_<source>` are
  parented to the original. Assignment is per exact component path + slot.
  - Transform, mesh, collision and profile are fingerprinted before and after; any difference
    aborts before the save.
  - The original material per slot is recorded once in
    `<project>/Saved/SUB01MaterialFix/backup.json`. The map is copied to
    `Saved/PrivateMapBackups/<ns>-materials-fix` first.
  - A second run changes nothing. `--restore` puts every recorded slot back.

### Texture content-equivalence (new guard)

Distinct texture assets are accepted only with a **texture parity file**:
`sub01.texture-parity.v1`, schema in the docstring of `tools/unreal_export_texture_parity.py`.
For every texture, all of these must hold:

- **Pixels.** Dimensions are identical to GLB image 15 / bufferView 157, and the decoded RGBA
  sha256 equals the reference. A maximum abs difference of 1/255 is allowed only with
  `reencode_proven` and a note.
- **Provenance.** The import data names the full-home GLB, or image 15 / bufferView 157.
- **Settings.** sRGB is true, compression is `TC_DEFAULT`, LOD bias is 0, and every
  `adjust_*` property is at its neutral default.

With no parity file, or on any mismatch, the guard refuses. Each defect is covered by a test.

Root steps (export is read-only; it saves no asset and changes no level):

```bash
UnrealEditor-Cmd <project>/Sub01HomeLab.uproject /Game/Sub01Home/ActualHome \
  -ExecutePythonScript="<repo>/tools/unreal_export_texture_parity.py --export <empty-dir> --quit" -unattended -nosplash
python3 tools/unreal_export_texture_parity.py --finalize <empty-dir> --glb <project>/SourceAssets/full-home.glb > texture-parity.json
python3 tools/unreal_home_materials_fix.py --mapping-check --inventory docs/proposed/actual-home-material-bindings-20261014.json --parity texture-parity.json
# apply then also takes --parity texture-parity.json
```

The export takes the textures' **source** pixels, before GPU compression. BC compression
changes individual texels but hardly the mean; the parity file records the settings that would
change the mean (sRGB, adjustments).

`bed-balanced` is **held** without a parity file. With one, its factors are recomputed from the
mean linear colour of the ACTUAL UE pixels (`texture_mean_used` in the report), not from the
repo `diff.jpg`. `bed-intended` does not depend on the texture mean: its factors are the exact
assembly tints.

## 10. Repair: bed albedo textures imported as normal maps (root parity export 13:51:49)

Root's export shows:
- **Pixels match.** All four bed albedo PNGs decode to exactly GLB image 15: RGBA sha256
  `0157e1e9c8197b2b81728df1e2fa2ac24da4199dad6ae1ca4d94a0b61f32b47e`, max diff 0, linear mean
  (0.28151, 0.40375, 0.60812), p99 (0.32778, 0.45641, 0.66539).
- **Settings are wrong.** All four UE assets have **sRGB False, TC_NORMALMAP**. The parity
  guard refuses them, and still does.
- **Effect on the render.** The originals are sampled without the sRGB decode. TC_NORMALMAP is
  BC5 (red and green only, blue reconstructed), so the bed colour in the render is not the
  texture's colour at all. The originals stay reported as "imported as a NORMAL MAP: refused
  as colour" and are never accepted.

Repair (all owned, reversible):
1. **Repair step.** `--repair-albedo-textures` first checks the bed mapping; it must be clean
   apart from the distinct-texture problem. It then requires each original to be exactly the
   measured state: sRGB False, TC_NORMALMAP, LOD bias 0, neutral `adjust_*`.
   - It runs `EditorAssetLibrary.duplicate_asset` into
     `/Game/Sub01Home/MaterialFix/Textures/SUB01_MatFix_Albedo_<Image_14x>`.
   - On the CLONE only it sets `srgb=True` and
     `compression_settings=TextureCompressionSettings.TC_DEFAULT`, and tags
     `sub01_matfix_duplicate_of=<original>`.
   - Before saving the clone alone, it verifies that the original's settings and `.uasset` sha256
     are unchanged, and that the editor's PNG export of clone and original are byte-identical.
   - Re-running it verifies the existing clones and creates nothing. It refuses if an existing
     clone's pixels, settings or tag differ.
2. **Clone mode.** With `--albedo-clones` (or the preset `albedo-color-clones`), the bed MICs
   override the real enumerated `BaseColorTexture` with the clone. With `bed-intended`, they
   also set `BaseColorFactor`. The real `NormalTexture` and everything else are inherited.
3. **Live guard.** A tint preset whose live base texture has sRGB False and no clone is refused.
   This also covers the sofa's `Image_43`, if its export shows the same defect; the sofa clone
   is a follow-up.
4. **Parity for clones.** The guard now takes a `clone_of` map. Each clone must:
   - sit under the explicit prefix `/Game/Sub01Home/MaterialFix/Textures/SUB01_MatFix_Albedo_`;
   - record `duplicate_of` equal to its original, with the import data still naming the GLB;
   - have a pixel hash equal to GLB image 15 (and the reference must be root's `0157e1e9…`);
   - have sRGB True and TC_DEFAULT.

   `--export --clones` exports the originals and the clones.
5. **Restore.** `--restore` puts the slots back, then deletes the owned MICs and clones (owned
