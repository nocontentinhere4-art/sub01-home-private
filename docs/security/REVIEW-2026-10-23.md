## 3. Findings

### S01 (High): machine time and starts have no cap

**Status after merge (611bf51): open.** The bridge is now a queue (`MAX_QUEUED = 3`, vagon_bridge.py:20), which bounds the links waiting, not the links per hour. Still missing: a cap per hour, a cap per viewer, a daily start budget, and any ledger row (costs.py has no Vagon service). The four S01 tests still fail as expected.

**Where.** `live_server.py:618-644` (the `open_url` branch of `handle_chat`, lines 638-643). `vagon_bridge.py:38-49` (`open_url_async` only takes a single-flight lock). `vagon_bridge.py:71-93` (`_open` starts the machine and waits up to 300 s, `vagon_pc.py:105-106`). `costs.py:46-48` and `70-78` (no Vagon service; it is not in the total). Introduced in fb79897; 3d855b5 let links through the filter.

**Exploit path.** No login. A viewer sends `open https://example.com/<n>`. The only limit is one message per 10 s per address (`chat.py:322`). Each accepted link runs one PowerShell `Start-Process` on the PC (`vagon_pc.py:127-133`), and starts the machine first if it is off. A link every 14 minutes keeps the machine on indefinitely if Vagon's idle timer counts run-script calls. That is unverified: `docs/design/vagon-pc/README.md:8-9` says only "seconds of idle time", and the test plan at line 65 says to check auto-stop on a pod. Addresses are free (S02, S06). The ledger never sees machine time, so `SUB01_CAP_TOTAL_USD` does not cover it. The cost is machine-hours at the Team rate, which the repository does not contain.

**Fix.** A gate that runs before any machine call and charges the cost ledger. It needs a price from the owner (`VAGON_USD_PER_HOUR`) and refuses everything without one. Section 4.1, 4.2, 4.3 and 4.4.

**Pinned by.** `test_links_are_capped_per_hour_for_all_viewers_together` (40 links from 40 addresses; at most 20 opened), `test_one_viewer_gets_a_few_links_an_hour` (12 links from one address; at most 6), `test_machine_starts_are_capped_per_day` (10 starts; at most 4), `test_a_started_machine_is_in_the_cost_ledger`.

**After the fix.** The `pc` fixture must call `vagon_bridge.configure(base_live.ledger, <price>)` and set `SUB01_CAP_VAGON_USD`. Until it does, `test_a_good_link_is_logged_by_host_only` (the positive control) fails, correctly.

### S02 (High): no rate for all viewers together

**Status after merge (611bf51): open.** `chat.check` (chat.py:350-367) still limits per address only, and nothing limits all viewers together. The test still fails.

**Where.** `chat.py:322` (the limit is per address). `live_server.py:620` (`chat_check`). `live_server.py:658-659` and `782-796` (each accepted message is sent to every client; `SUB01_MAX_WS` defaults to 400, line 774).

**Exploit path.** N addresses (a botnet, or one IPv6 /64, see S06) each get one accepted message every 10 s. Each accepted message runs the whole handler: a memory write, the stimulus, the eye and life hearing, one JSON encode, and one send per socket. Load grows with the addresses and the sockets, and nothing bounds it.

**Fix.** A window limiter for all viewers, passed to `check()` as `budget`. Section 4.5 and 4.3.

**Pinned by.** `test_chat_messages_have_a_global_rate` (40 messages from 40 addresses; at most 30 accepted). The 30 per minute is a proposal for the owner.

### S03 (Medium): link targets accept private, numeric and userinfo hosts

**Status after merge (611bf51): open.** `is_plain_link` (vagon_pc.py:272-274) checks the scheme, length and characters only, so private, numeric and userinfo hosts still reach the PC; the 13 sink tests and the 4 chat-level tests still fail. The base64 change (vagon_pc.py:277-288) stops script injection, which was never this finding. The chat filter still refuses two of the forms only through its EMAIL and PHONE rules (chat.py:32-33).

**Where.** `vagon_pc.py:30` (`WEB_LINK` checks only the characters). `vagon_pc.py:127-133` (`open_url`). `impulse.py:19-23` (URL_RE and the bare-domain rule) and `76-84` (`_first_url`). `vagon_bridge.py:76`.

**Exploit path.** The PC is a cloud Windows machine, so it cannot reach the owner's LAN directly. It can reach the cloud provider's internal services and metadata endpoints, and it shows a host the user did not type when the link has userinfo: `https://formo.family@203.0.113.9/`. Accepted today: `http://2130706433/`, `http://0x7f000001/`, `http://[::1]/`, `http://localhost/`, `http://10.0.0.5/`, `http://metadata.google.internal/`.

The chat filter refuses 169.254.169.254 and `user:pw@host` only by accident: its PHONE and EMAIL rules match them (the first test run showed this). `http://10.0.0.5/admin` and `http://[::1]/admin` pass the filter.

**Fix.** `vagon_pc.link_ok`, used by `open_url` and `_open`. Section 4.1 and 4.2.

**Pinned by.** `test_the_pc_refuses_private_numeric_and_userinfo_links` (13 cases, all accepted today), `test_a_private_link_does_not_start_the_machine` (4 cases that pass the filter).

### S04 (Medium): the pod file server answers HEAD without the token

**Status after merge (611bf51): open.** `analysis/pod/server.py` is unchanged on the merged tree, so HEAD still bypasses the token.

**Where.** `analysis/pod/server.py:27-29` overrides `do_GET` and `do_PUT` (both check the token). It does not override `do_HEAD`. CPython 3.13 `Lib/http/server.py:698` (`SimpleHTTPRequestHandler.do_HEAD`) calls `send_head()` with no check. Introduced in 51b4519.

**Exploit path.** `HEAD /<name>` with no token returns the headers of a file in `/out`: whether it exists, its size and its modification time. The bodies stay behind GET. The pod is reachable at `*.proxy.runpod.net`, and the names in `/out` (STATUS, log.txt, result archives) follow a known layout.

**Fix.** Gate `do_HEAD` like `do_GET`. Section 4.6.

**Pinned by.** `test_pod_server_head_needs_the_token` (xfail). Passing beside it: `test_pod_server_get_needs_the_token`, `test_pod_server_checks_the_token_before_any_upload`, `test_pod_server_refuses_to_start_without_a_token`.

### S05 (Medium): RateLimiter has no size bound and rebuilds its table on every message

**Status after merge (611bf51): partly fixed.** The CPU part is fixed: the limiter is an ordered dict that expires from the front (chat.py:319-333), so `test_a_message_does_not_walk_over_every_address` now passes (its counter also counts `values()` and `keys()`). The memory part is open: there is still no size bound, so `test_the_limiter_keeps_a_bounded_number_of_addresses` fails.

**Where.** `chat.py:280-292`. Each `allow()` rebuilds the whole dict (`self.last = {k: t for k, t in self.last.items() if now - t < self.window}`). Nothing caps the number of keys.

**Exploit path.** Send from many addresses. The table holds every address seen in the last 10 s, and each message walks all of them. The cost per message grows with the address rate, so the total cost grows with its square. Memory grows with it.

**Fix.** An `OrderedDict` in arrival order, expired from the front, with `MAX_KEYS = 4096`. Section 4.5. It keeps the behaviour `tests/test_sleep.py:589-602` pins (checked by hand: `set(lim.last) == {"a"}` at the end).

**Pinned by.** `test_a_message_does_not_walk_over_every_address` (counts the entries visited), `test_the_limiter_keeps_a_bounded_number_of_addresses` (20,000 addresses; at most 4,096 kept).

### S06 (Medium): the IPv6 viewer key is the full address

**Status after merge (611bf51): open.** `client_ip` (live_server.py:885-896 at 5be7288) still returns the full IPv6 address.

**Where.** `live_server.py:890-901` (`client_ip` returns the address unchanged). The key drives the chat limit, the per-address socket cap (`ws_per_ip`), and the vote and reaction limits.

**Exploit path.** One /64 holds 2^64 addresses. Each is a new key, so every per-address rule is unlimited for an attacker with one allocation.

**Fix.** Key IPv6 by its /64, and keep IPv4-mapped addresses as IPv4. Section 4.3.

**Pinned by.** `test_addresses_of_one_ipv6_64_share_a_client_key` (xfail). Passing beside it: `test_the_client_key_is_the_last_forwarded_entry_when_the_proxy_is_trusted`, `test_forwarded_headers_are_ignored_without_a_trusted_proxy`.

### S07 (Medium): auto-stop is set once per process, and never after a start

**Status after merge (611bf51): open.** `_ensure_ready` (vagon_bridge.py:172-186) starts a machine that is off and waits for it, but never sets the idle stop after a start. `configure_auto_stop` still runs once per process (live_server.py:2497-2498 at 5be7288).

**Where.** `vagon_bridge.py:52-68`. `configure_auto_stop` sets `_auto_stop_done = True` before the call (line 61), so a failure is never retried. `test_a_failed_auto_stop_is_recorded_and_not_retried` pins that. `_open` (lines 79-85) starts the machine without setting the idle stop.

**Impact.** If the boot-time PATCH fails (an HTTP 429, or the API not ready), or the machine is started again after an idle stop without this process, the machine runs with no idle stop until the process restarts. Every hour of that run is billed and unattended.

**Fix.** Set the idle stop after every start in `_open`. If that fails, stop the machine and raise. Section 4.2.

**Pinned by.** `test_auto_stop_is_set_again_when_the_bridge_starts_the_machine`. Compatibility: `tests/test_vagon_bridge.py:61-70` pins the exact call order `status, start, wait, open`, and its fixture records any unexpected call. The fix needs that test updated (section 8).

### S12 (Low, not measured): no frame budget per socket

**Status after merge (611bf51): open.** The frame loop (live_server.py:2002-2008 at 5be7288) still parses every text frame, with no budget per socket.

**Where.** `live_server.py:2008-2013`. Every text frame is parsed and filtered. Blocked frames are free by design: `chat.py:315-317` runs the filter before the per-address limit, and `tests/test_sleep.py:602` pins that a blocked message does not record its sender.

**Exploit path.** One socket can send blocked frames as fast as its link allows. Each costs a parse, the filter and an acknowledgement. I did not measure the cost of a flood. The tests time the filter on single inputs, all under 0.5 s.

**Fix.** A per-socket budget checked before `json.loads`. Section 4.3. Do not move the per-address limit in front of the filter: `tests/test_sleep.py:602` forbids it.

**Pinned by.** `test_each_socket_has_a_frame_budget_before_its_frames_are_parsed` (an AST check that an `.allow(` call comes before the first `json.loads` in `ws_handler`).

### S13 (Low): the RunPod runner installs its signal handlers after the pod exists

**Status after merge (611bf51): open.** `analysis/runpod_job.py` is unchanged on the merged tree; the handlers still come after the create.

**Where.** `analysis/runpod_job.py`. The pod is created at line 209 and recorded at 223. The SIGINT and SIGTERM handlers are installed at 231-232. The `try` that deletes the pod starts at 234.

**Exploit path.** An interrupt between 209 and 234 ends the process with the pod still running. The pod is recorded (or its pending name is), so the next run refuses until someone deletes it by hand. A billed pod can run unattended.

**Fix.** Install handlers that only set a flag at the top of `main()`, and make the create loop stop when the flag is set. Section 4.7.

**Pinned by.** `test_the_runpod_runner_installs_its_signal_handlers_before_the_first_create`.

### S14 (Info, defence in depth): the frame loop catches ValueError only

**Status after merge (611bf51): open (defence in depth).** The `except ValueError` (live_server.py:2007 at 5be7288) is unchanged. It is still not reachable with 4096-byte frames.
